# Milestone 4: Branching agents and competing attempts

**Status:** Waves 1 to 3 are done, and the Wave 4 review findings are fixed: core (`m4-fix-core`), UI
(`m4-fix-ui`) and app (`m4-fix-app`), with `mise run ci` passing (see [Wave 4 (fixes) status](#wave-4-fixes-status)).
What is left is the Wave 4 dogfood in a real window, which has not been done: synthetic clicks are not possible in
the environment the fixes were made in. The milestone is not complete until it is.

Milestone 4 lets a space **git-branch a whole agent**: its code, its `pi` session and its scratch state. Several
attempts at the same problem (Solutions 1, 2, 3) run side by side, each in its own hidden worktree. The user compares
their **outcomes** (repro, tests, diff, the agent's own summary) on a review sheet, discards the dead ends, and adopts
the winner back into the space.

## What a user can do at the end of it

1. **Fork attempts from a running writer agent** (graph panel, a space tab action, or `⌘⇧F`):
   - Choose how many attempts (1 to 4, 2 at first), and optionally give each its own instruction, for example "Solution 2: use a
     token bucket instead of a sliding window".
   - For each attempt, xctx:
     - snapshots the writer's worktree, uncommitted changes included, without touching it (`git stash create`);
     - makes a hidden worktree on `space/<slug>/attempt-<n>` from that snapshot;
     - writes the attempt's own `mise.<slug>.toml` with a fresh `PORT`;
     - copies the space's scratch folder to `/tmp/xctx-scratch/<slug>/attempts/<n>/`;
     - starts `pi --fork <the writer's session>` in the new worktree, so the attempt starts from everything the
       agent knew, with its instruction as the first message.
   - Forking is the user's action. An agent can only *propose* attempts (`attempt.propose`), and the proposal is a
     Plan Gate, because it adds agents and worktrees.
2. **Watch attempts run in parallel**: an attempt strip in the space tab shows each attempt's state (running, done,
   failed, discarded) and switches the panes to that attempt. Each attempt's agent reports its outcome over the socket
   (`attempt.report`: summary, tests run and passed, repro status), and xctx adds the diff against the fork point.
3. **Compare and decide on a review sheet** (`⌘⇧R` or when every attempt is done):
   - One column per attempt: the agent's summary, tests (passed/failed/not run), repro status, a diffstat and a
     changed-files list, with each file's diff a click away. Secrets are masked with `xctx_core::Redactor`.
   - **Discard** an attempt: its agent stops, and its worktree, branch, mise file and scratch folder are removed.
   - **Adopt** the winner:
     - It is merged into `space/<slug>`: a fast-forward when the space branch has not moved since the fork, else a
       merge commit. xctx checks for conflicts first (`git merge-tree`) and refuses with the conflicting files listed
       rather than leaving a half-merged worktree.
     - The writer pane continues from the winning session (`pi --session <winner>`).
     - The other attempts are offered for discard.
   - Adopting is never available on the control socket.
4. **Keep the session tree**: the space remembers which session each attempt forked from and which one was adopted
   (`attempts.json`), so the graph panel can show the lineage, and Ship or Discard of the space cleans up every
   attempt.

## Not in this milestone

- An automatic judge that picks a winner. The user decides; agents may only post findings.
- Forking across machines or into cloud runtimes.
- Attempts of more than one writer at once. Fork one writer; the rest of the graph is shared.
- Non-terminal plugin panes (Milestone 5).

## Decisions (settled in Wave 1)

- **Sessions: ids, not folders.** xctx names every agent's `pi` session itself and starts agents with
  `pi --session-id <id>`, which opens that session in the current directory or creates it. An attempt is
  `pi --fork <source id> --session-id <attempt id>`, run in the attempt's worktree. This was checked with pi 1.6: the
  fork, run from another directory, found its source by id, kept its context, and recorded the source file as
  `parentSession` in its header. That header is the lineage. pi's session storage stays where it is. The ids are
  `xctx-<slug>-<agent>` and `xctx-<slug>-<agent>-attempt-<n>` (`xctx_core::pi_session`). Agents that started before
  this change have no id; Wave 3 must give them one, or fork them from the newest session in their worktree's folder.
- **Branches.** Attempts are on `attempt/<slug>/<n>`. They cannot be under `space/<slug>/`, because git cannot have
  both a branch `space/<slug>` and branches below it. Worktrees go next to the space's, as `<slug>--attempt-<n>`.
- **Snapshot.** `git::snapshot_commit` stages the whole worktree into a temporary index. Uncommitted changes and
  untracked files are included, ignored files (the space's mise file among them) are not, and neither the
  worktree nor its index changes. The temporary index starts as a copy of the real one, so sparse-checkout,
  skip-worktree and assume-unchanged files are kept as committed. All attempts of one fork share that commit.
- **Attempt numbers.** A fork whose cleanup fails can leave a branch or folder behind. `AttemptSet::plan_fork_avoiding`
  skips numbers for which the caller's `taken` (`xctx_core::attempt_number_taken`) says true, and `record_fork` uses
  up every number to the plan's last.
- **Adopting.**
  - xctx refuses, changing nothing, when the space's worktree no longer matches the fork snapshot, since the writer
    kept working and that work would be lost. It also refuses when `git merge-tree` finds a conflict.
  - Otherwise the space's uncommitted work, which the attempt already has, is stashed (checked against the fork
    once more just before). Then the attempt is merged with `--ff`, whatever `merge.ff` says: a fast-forward when it
    can be. After the merge the stash is kept as `refs/xctx/pre-adopt/<slug>/<n>` and taken off the stash list; if
    the merge fails it is restored. Only a stash xctx made (a new `refs/stash`, found by its commit) is touched.
- **Limits and ports.** At most 4 attempts per fork, and at most 4 live in a space (`MAX_ATTEMPTS`). Each attempt takes its own `PORT`, which the
  caller allocates from the space range, avoiding the ports of spaces and of other attempts.
- **Ship and discard.** `xctx-core` does not know about attempt records, so refusing to ship or discard while
  attempts run, and cleaning them up afterwards, is done where the records are (Wave 3).

  - fork from the graph panel and the space tab, and spawn each attempt's panes;
  - switch panes between attempts;

## Wave 3 (app core) status

Done on `m4-app-core` (`mise run ci` passes), with nothing drawn yet:
- **Session ids.** Every agent pane bound to a graph agent runs a named `pi` session (`crates/xctx/src/agent_session.rs`).
  The id is recorded on the agent's graph node, in a new `AgentNode::session` field in `graph.json` (optional, so old
  files load). A new agent (a launch, a new lane) starts with `pi --session-id xctx-<slug>-<agent>` and records it.
  An agent with an id opens it. An agent from before this change, when resumed, has the newest session pi keeps for
  its worktree forked into its id (`pi --fork <file> --session-id <id>`), so it keeps its conversation. When no such
  session is found, it keeps `pi --continue` and records nothing. Panes bound to no agent behave as before.
- **Attempts in the workspace.** `Workspace::attempts` (`SpaceAttempts`, `attempts.rs`) loads each space's
  `attempts.json` on first use and keeps a change only once it is saved. Attempt terminals live in
  `SpaceTab::attempt_terminals` (number to `PaneTerminal`), not in the layout. They start when a fork records its
  attempts, and again when the space is opened. Attempts run `pi --fork <writer session> --session-id <attempt session>`
  with the instruction as the first message the first time, and their own session afterwards (whether it has started
  is read from pi's folder for the attempt's worktree). Each runs in its worktree with `XCTX_ATTEMPT_ID`, its `PORT`
  and `XCTX_SCRATCH_DIR`. Other panes get `XCTX_ATTEMPT_ID` set empty.
- **Fork, adopt and discard jobs** (`attempt_jobs.rs`), one at a time per space (`Workspace::attempt_jobs`). Quitting
  and closing the window wait for them.
  - Fork takes the store while it runs, so no launch takes a port meanwhile. Its ports avoid active spaces and every
    space's live attempts.
  - Adopt merges first. On a refusal (`ChangedSinceFork`, `AdoptConflicts`) the error is shown as `xctx-core` words
    it, and nothing else changes. Then the attempt is marked adopted, its agent is stopped and its worktree removed.
  - **Writer after adopt:** the writer's id becomes `xctx-<slug>-<agent>-adopted-<n>`, forked from the winning
    session the first time it starts in the space's worktree. Its pane restarts in it now when the tab is open, or
    the next time it opens.
  - Discard stops the attempt's agent, waits for it to exit, removes it and marks it discarded. When the removal
    fails, the agent is started again.
- **Scratch copy:** at fork time, the space's scratch artifacts are copied into `<space scratch>/attempts/<n>/` (the
  `attempts` folder itself is skipped). This uses `ScratchDir` in the app, so `xctx-channel` did not change. It is
  removed with the attempt, and with the space.
- **Control.**
  - `attempt.list` and `attempt.diff` wait for the startup mise check and are masked. `attempt.diff` runs git in the
    background.
  - `attempt.report` saves the outcome. When it finishes a round, it posts the Inbox notice "All attempts of round N
    in `<space>` are done; review them".
  - `attempt.propose` checks the agent (a writer), the count (1 to 4), the instructions (no more than the count) and
    the live-attempt limit, then posts the `FORK` gate. Approving it in the Inbox forks, and marks the item approved
    once the fork succeeded.
- **Ship and Discard of a space are refused** while it has live attempts, or while an attempt job runs. The message
  tells the user to adopt or discard them first. This is checked when the dialog opens and again when it is
  confirmed.

What the attempt UI calls (all on `Workspace`, `crates/xctx/src/attempt_jobs.rs`; the UI wave changed the return
types so the dialogs can show why something failed):
- `fork_attempts_then(&SpaceId, &AgentNodeId, Vec<Option<String>>, done, window, cx) -> Result<(), String>` (the fork
  dialog and an approved proposal; one entry per attempt), `done: FnOnce(&mut Workspace, Result<(), String>, &mut
  Window, &mut Context)`;
- `adopt_attempt(&SpaceId, number, window, cx) -> Result<(), String>` and `discard_attempt(..) -> Result<(), String>`
  (the review sheet), which call `Workspace::attempt_job_done` when the job ends;
- `attempt_set(&SpaceId) -> Result<&AttemptSet, String>`, the records for the strip, and for
  `xctx_attempt::comparison` (changed files: `xctx_core::attempt::attempt_changes`, off the UI thread);
- `attempt_terminal(&SpaceId, number) -> Option<Entity<TerminalView>>`, the terminal to show when the strip switches
  to an attempt;
- `attempt_jobs.contains(&SpaceId)`, to draw the buttons busy.

Left open or risky after the app core (the first two were fixed in the UI wave):
- ~~A launch's port did not avoid attempt ports.~~ `Store::allocate_port_avoiding` and `xctx_core::launch_avoiding`
  take extra taken ports, and the app's launch passes every space's live attempt ports.
- ~~Adopt did not stop the attempt's agent before its snapshot.~~ Adopt now stops it and waits for it to exit (as
  discard does) before `xctx_core::adopt_attempt`, and starts it again when the adopt fails or is refused.
- The checks for whether a session has started read pi's default layout: `~/.pi/agent/sessions/--<cwd>--/`, or the
  flat `$PI_CODING_AGENT_SESSION_DIR`. With a `sessionDir` set in pi's settings they find nothing. Old agents then
  keep `--continue`, and attempts fork again each time they reopen.
- A lane removed and added again under the same id would reopen the old lane's session.
- The session lineage in the graph panel, and the strip, fork dialog and review sheet, are the UI half.

## Wave 3 (UI) status

Done on `m4-app-ui` (`mise run ci` passes). The UI is in `crates/xctx/src/attempt_ui.rs`; what it shows is worked out
by plain functions there (chip states and labels, which attempts the strip lists, when Review shows, the review
view from `xctx_attempt::comparison`, which writer ⌘⇧F forks, the lineage line), with unit tests.

| Key or click | What it does |
| --- | --- |
| `⌘⇧F` in a space | Fork dialog for the writer bound to the focused pane, or the space's only writer; otherwise the status bar names the writers |
| Graph panel (`⌘G`), a writer's **Fork…** | Fork dialog for that writer |
| Attempt strip, **Fork…** | As `⌘⇧F` |
| `⌘⇧R` in a space, or the strip's **Review** | Review sheet on the space's latest round |

- **Fork dialog** (`Dialog::Fork`): count pills 1 to 4 (2 at first), one `PromptInput` per attempt (Enter forks, Esc
  closes), Fork runs `fork_attempts_then`, shows "Forking…" while it runs and the error if it fails, and closes on
  success. Cancel closes it at any time; the fork job carries on and reports in the status bar.
- **Attempt strip**: above the panes whenever the space has attempts (`attempt_set`). It lists every attempt of the
  latest round and any older one still live, labelled with its (masked) instruction or "Attempt n". Choosing an
  attempt shows its agent's terminal in the whole pane area, with the keyboard (`SpaceTab::shown_attempt`, kept per
  space); the space's panes keep running, undrawn. **Space** goes back. Review shows once an attempt of the latest
  round reported (done or failed).
- **Review sheet** (`Dialog::Review`): columns from `xctx_attempt::comparison`, masked. Each live attempt's changed
  files are computed with `attempt_changes` on the background executor ("Changes not computed yet" until then). A
  file click reads its diff (`attempt_tip`, then `git::diff_file` against the fork commit) in the background, masked
  with the workspace redactor. Adopt and Discard run the jobs; every action is disabled while `attempt_jobs` has the
  space; refusals (`ChangedSinceFork`, `AdoptConflicts`) show in the sheet. After an adopt or discard the sheet
  stays open and recomputes the changes, so the rest can be discarded. Close or Esc returns to the space.
- **Offer to review**: when `attempt.report` finishes a round, the status bar says so and to press `⌘⇧R` (the Inbox
  notice is as before).
- **Lineage**: each writer card with attempts in the graph panel has a line such as "attempts: #1 adopted, #2
  discarded" (`AgentGraphView::notes`); writers have a **Fork…** button (`AgentGraphView::on_fork`).
- The core fixes listed above (launch ports, adopt stopping the agent first).

Left for Wave 4:
- The UI was built and unit-tested, but not driven by hand in this wave (synthetic clicks do not work in this
  environment). Dogfood it: fork, switch the strip, review, adopt, discard.
- Adopted and discarded columns say "Changes not computed yet", since their worktree is gone; they could say
  what was merged instead (e.g. the adopt commit).
- Changes are computed when the sheet opens and after each adopt or discard, not when a report arrives while it is
  open.
- The writer card's buttons (Pause, Talk, Fork…) may be tight in the 196 px card.
- The review always shows the latest round; an older round with live attempts is reachable only through the strip.

## Wave 4 (fixes) status

The review findings are in [`reviews/m4-wave4/findings.md`](reviews/m4-wave4/findings.md). Core (C1, C2, W1 to W4)
and UI (U1 to U12) were fixed on `m4-fix-core` and `m4-fix-ui`; the app findings on `m4-fix-app`:
- **A1.** The legacy session lookup (`SessionStorage::newest_session_in`) skips sessions xctx named (`xctx-*`, by
  file name and header), so a helper's session in the writer's worktree is never carried over. A fork of a writer
  with no recorded session is refused: "start the writer's agent pane first".
- **A2.** An agent pane's session id is recorded on its graph node only once `pi` itself started
  (`spawn::runs_pi`: the terminal spawned and no fallback shell), not before.
- **A3.** A fork's source must be on disk (`pi_session::find_session`). When the writer's recorded id is an adopted
  id that has not started yet, the winning attempt's session is the source; otherwise the fork is refused, saying
  to start the writer and give it a message first (`agent_session::fork_source`). Forks pass the source's session
  file when it is known, not its id (`fork_source_arg`), both for attempts and for the writer after an adoption.
- **A4.** Adopt stops the space's writer agent as well as the attempt's, and waits for both to exit, before
  `xctx_core::adopt_attempt`. When the adopt fails or is refused, both start again.
- **A5.** Each attempt gets a random report token at fork (16 bytes of `/dev/urandom`, hex), kept in
  `attempts.json` (`Attempt::token`, empty in older files; a live attempt without one is given one when the space
  opens). It is exported as `XCTX_ATTEMPT_TOKEN` to that attempt's pane only (empty elsewhere); `xctx-ctl` sends it
  as `token=` with `attempt.report`, and the window refuses a report without the right token (`Forbidden`).
- **A7.** When marking an attempt adopted cannot be saved, nothing is cleaned up: the error is shown, the worktree
  stays, both agents start again, and adopting the same attempt again retries the record without merging twice
  (`Workspace::unsaved_adoptions`). Nothing else can be adopted, or that attempt discarded, meanwhile.
- **A8.** Removing what a fork made but could not record is the space's attempt job until it is done (quitting
  waits), and every leftover is named in the status bar. Every fork is planned with `plan_fork_avoiding` and
  `attempt_number_taken` (`attempts::plan_fork_skipping_leftovers`): the fork itself and the `attempt.propose`
  check, so leftovers never block later forks.
- **Suggestions.**
  - An attempt's or writer's agent is only started again once the stopped one has exited
    (`TerminalSession::is_alive`); meanwhile the status bar says it is still exiting, and after 15 s it says to
    quit and reopen xctx (there is no way to close one space's tab).
  - Attempt panes run as `XCTX_AGENT_ID=<writer>#attempt-<n>`. `contract.set`, `contract.agree`, `graph.pause`,
    `graph.resume` and `graph.remove_lane` refuse such an id (`Forbidden`); `channel.post` from it is labelled
    as the attempt, not the writer.
  - When `attempts.json` cannot be read, a writer whose session comes from an adopted attempt is not started, and
    the error is shown, instead of opening an empty session.
  - While a fork runs, the fork dialog draws the instructions it was started with as text instead of the inputs,
    and keeps the keys (Esc still closes it).
  - The `refs/xctx/pre-adopt/<slug>/*` backups are deleted when the space is shipped or discarded (best effort;
    failures show in the status bar).
  - Not done: the two nested scroll containers of the review sheet (the app's wrapper and `ReviewSheet`'s own)
    were kept, since dropping one could not be checked by eye here.

Still unverified, for the dogfood:
- Nothing of Milestone 4 has been driven by hand in a real window: the fork dialog, the strip, the review sheet,
  adopt and discard, and the writer stopping and restarting around an adopt. Only unit and integration tests ran.
- The checks for whether a session is on disk read pi's default layout (see the app core notes above); with a
  `sessionDir` set in pi's settings, forks are refused because the source is never found.
- `loop.advance` and `loop.set_autonomy` name no agent, so an attempt's pane can still call them as any pane can.
- The report token protects against panes reporting for the wrong attempt, not against a local process that reads
  `attempts.json`.
