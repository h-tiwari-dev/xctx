# Milestone 2: Control socket, Parent Agent, and Inbox

**Status:** All four waves of Milestone 2 are complete (all Wave 4 review findings fixed and verified with `mise run ci` + `mise run bundle`). Ready for manual dogfooding and Milestone 3.

Milestone 2 turns xctx from a human-driven workspace into an **agent-drivable harness**: agents can inspect and reshape
the window over a local control socket, an always-on **Parent Agent** drafts and coordinates spaces from Home, and the
**Inbox** gates every action that launches or widens a space.

## What a user can do at the end of it

1. **Drive xctx over a local control socket** (CLI or agent tool): list spaces, inspect panes, split/close/focus/zoom
   panes, mount or reshape layouts (`Dev`/`Debug`/`Review`), draft a space, and post status messages or inbox items.
2. **Talk to the Parent Agent from Home**: describe a task in natural language; the Parent Agent queries `RepoIndex`,
   proposes a space draft (repos + reasons + initial shape), and submits it to the **Plan Gate** — it writes no code and
   never launches without approval.
3. **Review and act in the Inbox**: approve or edit pending space launches, approve space widenings (adding repos or
   switching to `MISE_ENV=production`), and resolve missing `mise` required environment variables (with mise's own help
   text).
4. **Trust secret redaction**: secret env values declared in `mise` are masked in agent-facing control responses, shared
   notes, and inbox previews.

## Not in this milestone

Per-space orchestrators, inter-service contracts/channels, autonomous `write -> test -> probe -> review` loops, the
agent graph view (Milestone 3), agent forking / competing attempts (Milestone 4), and non-terminal plugins (Milestone 5).

## Crates

Existing M1 crates (`xctx-core`, `xctx-layout`, `xctx-term`, `xctx-term-view`, `xctx-ui`, `xctx`) stay in place.
Milestone 2 adds:

| Crate | GPUI | Owns |
| --- | --- | --- |
| `xctx-control` | no | newline-delimited JSON-RPC protocol, Unix domain socket server/client (`$XCTX_CONTROL_SOCKET`), request/response types, capability/auth checks, and a small `xctx-ctl` CLI binary for agents and scripts |
| `xctx-inbox` (or module in `xctx-core`) | no | Inbox item model (`PlanGate`, `MissingEnvVar`, `SpaceWiden`, `Notice`), persistence, approve/reject transitions, and `mise` required-var inspection + secret redaction |

Existing crates extended in M2:
- `xctx-core`: `mise` required-var check (`mise env --json` / config inspection) and secret redaction helper; optional
  `space.widen` (add a repo worktree to an active space after plan-gate approval).
- `xctx-ui`: Inbox drawer/panel component, Plan Gate card component, and Parent Agent drawer/panel on Home.
- `xctx`: bind the control socket on startup (export `XCTX_CONTROL_SOCKET` to spawned panes), dispatch control commands
  onto the GPUI app loop, host the Parent Agent `pi` session on Home (read-only / no-code system prompt + control tools),
  and wire Inbox notifications + approvals.

## Protocol surface (initial `xctx-control` methods)

Reference the Swift prototype's socket framing at `git show 413b816:Sources/WorkspaceCore/Control.swift` for inspiration,
and design a clean versioned JSON-RPC 2.0 / NDJSON protocol over Unix domain socket (`$XCTX_DATA_DIR/control.sock` by
default, overridable via `XCTX_CONTROL_SOCKET`):

- `ping` -> `{ version, pid }`
- `space.list` -> active spaces, slugs, ports, shapes, repos
- `space.draft` (`{ task, repos? }`) -> creates/updates a draft and posts a `PlanGate` item to Inbox (never auto-launches)
- `space.reshape` (`{ space, shape }`) -> non-destructive reshape (`dev` / `debug` / `review`)
- `layout.get` (`{ space }`) -> current `PaneTree` + pane roles
- `pane.split` (`{ space, pane?, axis, kind?, repo? }`)
- `pane.close` (`{ space, pane }`)
- `pane.focus` (`{ space, pane }`)
- `pane.zoom` (`{ space, pane? }`)
- `inbox.list` / `inbox.post` -> read or post items requiring user attention
- `status.set` (`{ level, message }`) -> display status banner

### What exists

| Area | Where | Notes |
| --- | --- | --- |
| Control protocol, server, client, `xctx-ctl` | `crates/xctx-control` | JSON-RPC 2.0 over NDJSON. Socket at `$XCTX_CONTROL_SOCKET`, else `<data dir>/control.sock`. Methods: `ping`, `space.list`, `space.draft`, `space.reshape`, `layout.get`, `pane.split/close/focus/zoom`, `inbox.list/post`, `status.set`. | Inbox model and store | `crates/xctx-inbox` | Items are `PlanGate`, `SpaceWiden`, `MissingEnvVar` and `Notice`, kept in `<data dir>/inbox.json`. A fresh Inbox gets `welcome_notice()`. |
| mise checks, redaction | `xctx-core`: `mise_env.rs`, `redact.rs`, `mise.rs` (`set_space_var`) | `MiseRunner::inspect` runs `mise env --json --redacted` and steps through every missing required variable. `Redactor` masks values as `[REDACTED:NAME]`. |
| UI components | `xctx-ui`: `inbox.rs`, `plan_gate.rs`, `parent_agent.rs`, `status_bar.rs` (Inbox count) | Render tests in `crates/xctx-ui/tests/m2_render.rs` click through debug selectors. |
| App wiring | `crates/xctx/src`: `control.rs`, `inbox_view.rs`, `parent_agent.rs` | Socket requests run on the UI thread. Pane operations take a space id (`*_in` in `space_tab.rs`). Plan Gate approval launches through `Workspace::start_launch` (`home.rs`). The Parent Agent is `pi --continue --tools read,bash` with `PARENT_AGENT_PROMPT`, run in `<data dir>/parent-agent/`. |

Known gaps, by design for now:
- Approving a `SpaceWiden` says it is not supported. Nothing posts one yet, and widening needs a `space.widen` in `xctx-core`.
- Every socket client is recorded as `Source::Agent`, so Plan Gates from the Parent Agent say "proposed by an agent". A separate socket (or a token) for the Parent Agent would let the app tell them apart.

### Wave 4 review findings to fix

The three reviewers read the code only; they did not build or run anything. Their full reports, with file:line references and suggested fixes, are in [`docs/reviews/m2-wave4/`](reviews/m2-wave4/). None found a critical issue. Check each warning against the code, then fix it or strike it here with the reason. Suggested order:

**Safety and correctness first**
- [x] app 1: control requests take keyboard focus from an open dialog or the pane being typed in. Fixed (`may_focus_pane_of` checks `is_shown(id) && dialog.is_none()`).
- [x] app 3: a control request on a closed space opens it and starts all of its agents. Fixed (`resolve_open_space` returns `RpcError::conflict("space X is not open; open it first")`).
- [x] app 2: `pane.split kind=agent` starts `pi --continue` on the same session as the space's existing agent. Fixed (`AgentStart::Fresh` when another agent already works in that worktree).
- [x] app 8 and app 7: a Plan Gate can be launched twice (approve failing after the launch succeeded, or a double click), and can be edited while it launches. Fixed (`plan_launching` guards + `launched_plans` tracking).
- [x] control 1: two windows starting at once can delete each other's socket. Fixed (exclusive `flock` on `<socket>.lock` held for server lifetime).
- [x] control 4: a request that timed out still runs later, so a retry can split twice. Fixed (`Responder::is_cancelled()` checked in `handle_control`, `flush_control_drafts`, and `flush_inbox_lists`).

**Secrets**
- [x] inbox 1 / app 5: a value from Set value is not masked after a restart. Fixed (`set_space_var` writes `{ value = ..., redact = true }` and UI wording updated).
- [x] inbox 4 / app 6: `inbox.list` answers before the first mise check has filled the redactor. Fixed (`mise_ready` + `pending_inbox_lists` queue).
- [x] control 5: the client does not check that the socket's owner is the same user. Fixed (shared `peer_is_same_user` via `getpeereid` on connect).

**Robustness**
- [x] control 2: `xctx-ctl` misreads `key=a:=b`. Fixed (split on first `=`, JSON if key ends with `:`).
- [x] control 3: if a connection thread cannot be spawned, the stream is left open and the client hangs. Fixed (removes from map and calls `shutdown(Both)`).
- [x] inbox 2: agents can post pending notices without limit. Fixed (capped at `MAX_PENDING_AGENT_NOTICES = 100`, auto-dismissing oldest).
- [x] inbox 3: a dismissed missing variable comes back at every startup check. Fixed (`sync_missing` suppresses dismissed `(dir, mise_env, name)` and skips no-op writes).
- [x] app 4: the Parent Agent's "writes no code" is only a prompt: it has bash and runs inside the data directory. Fixed (runs in sibling `<data dir>-parent-agent` directory outside the data dir, and UI/docs state the no-code rule is advisory).

The suggestions in the reports (connection caps, a `NO_COLOR` env for mise, timeouts on mise runs, more isolated mise test environments, and so on) are optional.

### Notes for working here

- Tests must never touch the user's real mise config. The mise tests isolate mise through `MISE_TRUSTED_CONFIG_PATHS`, `MISE_CONFIG_DIR`, `MISE_DATA_DIR`, `MISE_STATE_DIR`, `MISE_CACHE_DIR` and `MISE_GLOBAL_CONFIG_FILE` (see `crates/xctx-core/tests/mise_env.rs`). Never run `mise trust` on a temp directory.
- The old Swift prototype (`PixelWorkspace.app`, untracked in the repo root) shares `~/Library/Application Support/xctx` and `control.sock`. xctx reads its version-less `spaces.json`, but do not run both at once.
- To screenshot the window for a visual check, find its id with `CGWindowListCopyWindowInfo` (the window named `xctx`), then run `screencapture -x -o -l <id> file.png`. Synthetic clicks need Accessibility permission and do not work here.
- The review was run with `pi -p --no-session --tools read,bash --append-system-prompt <docs/reviews/m2-wave4/reviewer-prompt.md> "<area>"`, three in parallel.
