# Milestone 6: The shell — a UX and visual overhaul

**Status:** In progress. Waves 0–1 are merged. The shell part of Waves 2–3 is on branch `ui-overhaul` (see
[What has shipped](#what-has-shipped)); the Inspector, the Inbox overlay and the Parent Agent dock are still to do.

## What has shipped

Captured from a dev build on a throwaway data directory, rendered off screen and composited over a gradient that
stands in for the blurred desktop: [a space](reviews/m6-shell/space.png), [the palette](reviews/m6-shell/palette.png).

- **Translucent window.** `WindowBackgroundAppearance::Blurred` with `Theme::translucent()` (chrome 62%, panes 74%
  opaque). Terminals draw no default background of their own; the pane, card or attempt frame around them is
  their one `surface` layer. On by default; "Make window opaque/translucent" in `⌘K` switches it, and the choice is
  kept in `ui.json` in the data directory (with the Roster's collapsed state).
- **Title bar row.** The system title bar is transparent and the app owns dragging (`app_owns_titlebar_drag`): the
  row holds the traffic lights, the Roster toggle, the shown view's title, a search pill for the palette, and for a
  space its shape control, Graph, + Agent, + Repo, Discard and Ship. Every part of it that is not a control moves
  the window (`window_drag_area`). Branch and env moved to the status line; only a production env shows here.
- **Roster** (`⌘B` collapses it to a rail). Replaces the tab bar, which is deleted. Spaces are grouped Needs you /
  Running / Idle with their agents nested; `⌘1`–`⌘9` and Home's cards follow Roster order. A space counts as
  running when an agent's terminal runs, not only when the graph says so.
- **Command palette** (`⌘K`): every action with its chord, every space, every agent of a loaded graph, and the
  shown space's tools. The status line's key-hint wall is gone; it shows `⌘K Commands`.
- **Drag and drop.** A pane header dropped on another pane's side splits it there, in its middle swaps the two
  (`PaneTree::drop_pane`, `DropEdge`). A tool dragged out of the dock opens beside the pane it is dropped on (or
  moves its pane there when it is open). Files dropped from Finder on a terminal are typed in shell-quoted
  (bracketed paste when the program asked for it). Folders dropped on Home's composer are indexed.
- **Look.** Icons in pane headers and their accessories, rounded pane frames with a focus ring, hover washes that
  read on translucent surfaces (`Theme::hover`), Home as a composer card with a grid of space cards.

## Why this milestone

Milestones 1 to 5 built every capability in [`design/README.md`](../design/README.md). Each one added its own
button, panel, dialog and key chord to the window, so the window now mirrors the order the features were built in,
not the way a person works. Milestone 6 adds no capability. It rebuilds the window's shell around three questions
the user asks all day:

1. **What needs me?** (gates, blocked loops, finished attempts)
2. **What is everyone doing?** (every space, every agent, at a glance)
3. **Let me steer this one.** (focus one agent, talk to it, come back)

The UX reference is omp (oh-my-pi), a terminal coding agent. It answers the same three questions for one session
and its subagents; xctx has to answer them for many spaces. What is taken from it is listed under
[What we take from omp](#what-we-take-from-omp).

## What xctx is

xctx is not a multiplexer. Multiplexing panes was Milestone 1; everything since is about the unit above the pane.
A **space** is one task, with its worktrees across repos, its own mise environment and port, a graph of agents
(orchestrator, one writer per repo, read-only helpers), a shared contract and channel, a loop with an autonomy
level, competing attempts, and plugin panes. The window is where a person launches, watches, approves and ships
those. The accurate category is a **task-first agent workspace**: closer to a control room than to tmux.

Naming is decision D1 below.

## The shell

```
┌────────────┬──────────────────────────────────────────────┬────────────┐
│ ROSTER     │ checkout-retry   Write ▸ Test ▸ Probe ▸ Rev  │ INSPECTOR  │
│            │ within budget 3/8                     [Ship] │ Graph      │
│ ⌂ Home     ├──────────────────────┬───────────────────────┤ Shared     │
│            │ ● writer · api       │ ◐ tests               │ Attempts   │
│ NEEDS YOU  │                      │                       │ Plugins    │
│ ! checkout │                      │                       │            │
│   ◐ writer │   terminal           │   terminal            │ (selected  │
│   ! tests  │                      │                       │  tab's     │
│ RUNNING    │                      │                       │  content)  │
│ ● billing  ├──────────────────────┴───────────────────────┤            │
│ IDLE       │ ⎇ space/checkout · env checkout · :4012      │            │
│ ○ docs     │ 2/3 agents · ✉ 2                    ⌘K       │            │
└────────────┴──────────────────────────────────────────────┴────────────┘
```

### Roster (left, `⌘B`)

Replaces the tab bar. Spaces are grouped by state in this order: **Needs you**, **Running**, **Idle**. Each space
row has a state glyph, its title and its age since last activity. Its agents nest under it with their role colour,
state glyph and one line of current activity. Enter or click focuses the space, or the agent's pane. `⌘1` to `⌘9`
keep working and follow Roster order. Collapsed, it is a rail of state glyphs.

A space's state is a rollup, worst first: a pending Inbox gate or a paused loop is *needs you*; a blocked loop or
dead pane is *failed*; any agent running is *running*; else *idle*.

### Space header (top of the centre)

Replaces the tab bar's right-hand cluster and the loop bar. It shows the title, the loop as a four-step stepper
with the autonomy level and budget, and **Ship** as the one primary button. Dev/Debug/Review reshaping and Discard
move to the palette and to a `…` menu. Discard stays behind its confirmation dialog.

### Inspector (right, `⌘I`)

One panel with four tabs, replacing five surfaces: **Graph** (agents, pause/resume, lanes), **Shared** (contract,
channel, findings, notes), **Attempts** (fork, compare; the review sheet stays a full overlay opened from here),
**Plugins** (mounted and available; mounting no longer needs a modal). `⌘G` and `⌘⇧P` open it on their tab.
Below 1100px of window width the Inspector overlays the panes instead of shrinking them.

### Inbox overlay (`⌘⇧I`)

A right-anchored overlay over whatever is shown. `j`/`k` select, `a` approves, `d` denies, Enter opens the item's
detail (plan gate, write gate), Esc closes. A new gate raises a toast with Approve / Open, and the space moves to
*Needs you* in the Roster. Nothing navigates to Home.

Gates are not equal. A gate that adds `production`, runs a write tool or trusts a repo plugin is drawn in the
danger tone, sorts first, and cannot be approved from the list: `a` opens its detail, where Approve is a second,
deliberate action.

### Command palette (`⌘K`)

Every action in `keymap.rs` plus every space, agent and plugin, fuzzy-matched, with its key chord shown beside it
and recent commands first. Prefixes narrow it: `>` actions, `@` agents, `#` spaces. This is where a new feature
becomes discoverable from now on; a feature does not get a new button by default.

### Home (`⌘0`)

Composer first: the task prompt is centred and is the only thing with emphasis. The draft opens as a card under it
(repos with match reasons, add/drop, Launch). Below: **Needs you** (the same items as the Inbox), then living
spaces as cards. Indexed folders move to Settings (`⌘,`). The Parent Agent leaves Home and becomes a dock that
opens from anywhere with `⌘J`.

### Status line

Segments only: branch, mise env (danger tone when `production`), port, `running/total` agents, inbox count, and
`⌘K` at the right edge. Banners become toasts.

## Visual system

- **Tokens.** `Theme` grows from 16 colours to a semantic set, and the terminal's ANSI palette moves into the
  same theme so chrome and terminals match. Every value, the mapping from today's fields and the implementation
  steps are in [`m6-theme.md`](m6-theme.md).
- **Dark and light**, following the system appearance, switched at runtime.
- **Type.** The system UI font for chrome, one mono token (replacing the 17 `"Menlo"` literals) shared with the
  terminal's configured font. Five sizes stay; weights limited to regular and semibold.
- **Icons.** One `Icon` component over a small SVG set (Lucide, ISC licence) embedded in the binary: about 30
  icons for states, roles, pane kinds and actions. Unicode glyphs in chrome go.
- **Motion.** Overlays fade and slide in 140ms; a spinner on anything running; a slow pulse on *needs you*.
  Nothing else animates. A reduced-motion setting turns all of it off.
- **Density.** A 4px grid, 28px rows in the Roster and Inspector, pane headers stay 24px. Focused pane: a 1px
  focus ring and a full-strength header; unfocused panes dim their header only, never the terminal.

## Performance

The goal is no dropped frames in any interaction. The number is not 60: a MacBook Pro display refreshes at 120Hz,
so the budget is **8ms per frame**, and what a user feels as stutter is a single frame that takes 30ms, not an
average. The budgets, all measured in a release build:

| What | Budget |
| --- | --- |
| Any frame while scrolling, resizing a split, dragging a divider, or animating an overlay | 8ms at p99 |
| Key press in a terminal pane to the glyph on screen | one frame after the program echoes |
| Opening the palette, the Inbox overlay or the Inspector | first frame within 16ms of the key |
| Switching space | first frame within 16ms; panes may fill in after |
| Four panes printing at full speed (`yes` in each) | UI stays at 8ms; the terminals may skip intermediate frames |

Rules every branch of this milestone follows, so the budgets hold by construction:

1. **Nothing slow on the main thread.** No file, git, process, socket or `mise` call in a `render`, an action
   handler or an event handler; they go through `cx.background_executor()` and come back with the result, the way
   `start_launch` in `home.rs` does. Stores that write to disk before returning are called from the background.
2. **`render` only reads.** It builds elements from state already in memory. `Workspace::render` calls
   `sync_plugin_panes` and `refresh_plugin_panes` on every frame today; they move to the events that change panes.
3. **Long lists are virtualised.** Any list that can pass 50 rows (channel, logs, palette results, Roster, review
   diffs) uses `uniform_list`. There is none in the code today.
4. **A notify repaints as little as possible.** State that changes often (a spinner, a terminal, a toast) lives in
   its own entity, so its `cx.notify()` does not re-render the workspace.
5. **Motion is opacity and offset only**, at most 160ms, and never delays input: a key pressed during an
   animation acts at once.
6. **Terminal output is coalesced** to one snapshot per frame. `TerminalView` already does this with
   `wakeup_pending`; keep it.

Measurement comes first (`m6-kit`, Wave 1): a frame-time overlay in debug builds (`⌘⇧.`) that shows the last
frame, the p99 over five seconds and a count of frames over 8ms, and a log line for every frame over 16ms naming
the view. Wave 4 runs the table above with the overlay on and fixes what fails. The workspace `Cargo.toml` has no
`[profile.release]` section; add one (`lto = "thin"`, `codegen-units = 1`) before measuring.

## Building xctx in xctx

The test of this milestone is that it is built inside the app it changes. That needs three things:

- **Two instances, never one store.** The xctx you work in (the host) is a release bundle. The xctx you are
  changing runs from a space's worktree with `mise run dev`, and must use its own data directory and control
  socket. Panes do not get `XCTX_DATA_DIR` today, so a dev build started in a pane opens the host's store.
  `mise.<slug>.toml` should set `XCTX_DATA_DIR` to a directory under the space's scratch directory.
- **The host is replaceable without losing work.** Updating the host means quit and reopen; every space, layout
  and agent session must come back (`pi --continue` already does this for agents). The new shell state (Roster
  collapsed, Inspector tab, focused pane) is persisted with the layout.
- **A dev instance looks different.** A window not running from the release bundle shows a `DEV` badge in its
  status line and uses `agent[5]` as its accent, so the two windows are never confused.

## Decisions

Defaults are chosen so work can start; change any before Wave 1 ends.

- **D1 Name.** Keep **xctx** ("cross-context") as the product and binary name, with the line "a task-first
  workspace for teams of agents". `design/README.md` calls the product "Spaces"; on macOS that collides with
  Mission Control's Spaces and cannot be searched for. "Space" stays as the noun for one task.
- **D2 Roster, not tabs.** A vertical roster costs about 220px of width and buys per-agent state and more than
  nine spaces. It collapses to a 44px rail. The tab bar is deleted, not kept as an option.
- **D3 Light theme is in scope**, because the token work is the same work.
- **D4 Icons are Lucide**, embedded; no icon font.
- **D5 Esc belongs to the terminal.** When a terminal pane has focus, Esc always goes to the program in it (`nvim`,
  `pi`). Layered Esc applies only when focus is in chrome. Every overlay therefore also closes on its own chord.
- **D6 Single-letter keys only inside overlays** that own focus (Inbox, palette, Inspector lists). Global actions
  stay on `⌘` chords, since any other key belongs to the focused terminal.
- **D7 The control socket does not change.** `layout.*`, `pane.*` and `graph.*` keep their meaning; the Parent
  Agent drives the new shell with the methods it has. New methods (`inspector.show`, `palette.run`) are out of
  scope.

## Not in this milestone

New agent, loop, attempt or plugin capability. Voice and canvas task entry. A settings UI beyond indexed folders
and theme choice. Custom user keybindings. Platforms other than macOS.

## Waves

Each branch is its own git worktree off `m6-base` and merges back into it. Branches in one wave touch disjoint
files.

0. **Wave 0 — Baseline and decisions.**
   - Home is captured in `docs/reviews/m6-baseline/`. Capture the rest there: a space in each shape, the graph
     and shared-space panel, the attempt strip, fork dialog, review sheet, plan gate, Plugins menu and each
     plugin pane. Settle D1 to D7.
1. **Wave 1 — Foundations (parallel).**
   - `m6-theme`: Theme v2 tokens, dark and light, system appearance, type and mono tokens, the terminal palette
     from the theme; migrate every existing component and the plugin views. No layout change, so the app must
     look the same or better at the end of this branch.
   - `m6-kit`: `Icon` and the SVG set, `Spinner`, `Overlay` (scrim, focus trap, close chord), `Toast`, motion
     helpers, and the gallery binary.
   - `m6-nav`: the `xctx-nav` crate (roster rollup, palette matcher).
2. **Wave 2 — Shell components (parallel, in `xctx-ui`, one file each, shown in the gallery).**
   - `m6-roster`: `Roster` and its collapsed rail.
   - `m6-header`: `SpaceHeader` with the loop stepper, and `StatusLine`.
   - `m6-inspector`: the `Inspector` shell and its four tabs over the existing graph, shared-space, attempt and
     plugin views.
   - `m6-overlays`: `CommandPalette` and `InboxOverlay`.
3. **Wave 3 — Integration (in `crates/xctx`, sequential: one owner).**
   - `m6-shell`: swap the tab bar for the Roster and header, mount the Inspector, the overlay stack and focus
     rules (D5, D6), the new keymap; delete the replaced components.
   - `m6-home`: the composer-first Home, the Parent Agent dock, Settings for indexed folders and theme.
4. **Wave 4 — Review and dogfood.**
   - A reviewer pass over `xctx-ui` and `xctx` for focus bugs (keys reaching a terminal from an overlay and the
     reverse), contrast in both themes, and layout from 900px to full screen.
   - Dogfood: run a two-repo space end to end using the keyboard only. The bar to pass: a gate is approved without
     leaving the space, any action is reached from `⌘K`, and a space that needs you is visible from any other
     space within one glance at the Roster.
   - If time allows: themes as files in the data directory with live reload.

## Visual proof

`screencapture -l <window id>` works once the terminal running the agents has Screen Recording permission; the
window id comes from `CGWindowListCopyWindowInfo`. Home can be put in any state without input, by seeding
`spaces.json` in a throwaway `XCTX_DATA_DIR` and posting gates with `xctx-ctl`. Showing a space cannot: no control
method switches the view, and sending keys or clicks needs Accessibility permission as well. Until that is granted,
space-view screenshots come from the user. The headless GPUI render tests check structure only, not looks.
