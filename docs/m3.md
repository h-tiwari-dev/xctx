# Milestone 3: Multi-agent graphs, shared contracts, and autonomous loops

**Status:** In progress — Wave 1 foundations starting on `m3-base`.

Milestone 3 turns a space from independent terminals into a **coordinated multi-agent graph** with an orchestrator,
strictly scoped writers (at most one writer per repo), read-only helpers, a shared contract & channel, structured
`write -> test -> probe -> review` loops with autonomy controls, and an interactive **Agent Graph** view.

## What a user can do at the end of it

1. **Inspect and steer the Agent Graph** inside any space (`⌘G` or tab-bar Graph button):
   - See the hierarchy: one **Orchestrator** per space, one **Writer** per repo, and read-only **Helpers** (`Tests`,
     `Reviewer`, `Probe`).
   - Pause or resume any agent, add or remove helper/writer lanes (respecting at most one writer per repo), and jump
     straight to talk to a specific agent pane.
2. **Coordinate across repos via the Shared Space (Contract, Channel, Findings, Notes, Scratch)**:
   - Writers never edit each other's repo. They communicate over the space's **Channel** and agree on a versioned
     **Contract** (API shape, event payload, or schema) held by the space and verified by helpers.
   - All agent-facing channel/contract/finding reads pass through `xctx_core::Redactor` so secrets stay masked.
   - Intermediate artifacts live in `/tmp/xctx-scratch/<slug>/` and are cleaned up on Ship/Discard.
3. **Run structured loops with explicit autonomy**:
   - Configure a space's loop (`Write -> Test -> Probe -> Review`) and autonomy level:
     - *Ask each step* (pauses at each stage transition and posts an Inbox gate)
     - *Within budget* (runs autonomously up to `max_iterations` / `max_turns`, then pauses)
     - *Until checks pass* (advances through stages until tests/review pass or a failure blocks)
4. **Approve Space Widenings end-to-end**:
   - Agents can propose widening an active space (`space.widen_propose` -> `SpaceWiden` item in Inbox). Approving in
     the Inbox runs `xctx_core::space::widen` to add the new repo worktree(s) (`space/<slug>` + `mise.<slug>.toml`)
     and/or enable `MISE_ENV=production`, and adds the new writer lane to the graph.

## Not in this milestone

Git-branching an entire live agent / competing parallel attempts (`pi --fork`, Solutions 1/2/3 comparison — Milestone 4),
and non-terminal plugin panes (Browser, API client, Logs, DB, Jira, Figma — Milestone 5).

## Crates

Existing crates (`xctx-core`, `xctx-layout`, `xctx-term`, `xctx-term-view`, `xctx-ui`, `xctx-control`, `xctx-inbox`,
`xctx`) stay in place. Milestone 3 adds two UI-free crates:

| Crate | GPUI | Owns |
| --- | --- | --- |
| `xctx-graph` | no | Per-space agent graph (`AgentNode`, `AgentRole`, `AgentState`, `GraphEdge`, `AgentGraph` enforcing <=1 writer per repo), structured loop state machine (`LoopStage`, `AutonomyLevel`, `LoopRun`), and atomic persistence (`<data dir>/spaces/<slug>/graph.json`) |
| `xctx-channel` | no | Shared space store (`Contract`, `ChannelMessage`, `Finding`, `Note`, bounded history, redaction via `xctx_core::Redactor`, atomic persistence in `<data dir>/spaces/<slug>/shared.json`) and `/tmp/xctx-scratch/<slug>/` artifact helper |

Existing crates extended in M3:
- `xctx-core`: `space::widen` (add new repo worktree(s) and/or production flag to an active space with rollback on failure).
- `xctx-control`: M3 JSON-RPC methods & `xctx-ctl` subcommands (`graph.get`, `graph.pause`, `graph.resume`,
  `graph.add_lane`, `graph.remove_lane`, `channel.post`, `channel.list`, `contract.get`, `contract.set`,
  `contract.agree`, `loop.status`, `loop.advance`, `loop.set_autonomy`, `space.widen_propose`).
- `xctx-ui`: `AgentGraphView`, `SharedSpacePanel` (Contract / Channel / Findings / Notes), and `LoopBar` (stage + autonomy selector) with headless GPUI render tests.
- `xctx`: host per-space `AgentGraph` & `SharedSpace`, dispatch M3 control methods, wire `SpaceWiden` Inbox approvals to `space::widen`, export `XCTX_AGENT_ID` / `XCTX_AGENT_ROLE` / `XCTX_SCRATCH_DIR` to spawned panes, and add the Graph / Shared-Space panel toggle in space tabs.

## Waves

1. **Wave 1 — Foundations (in parallel, off `m3-base`):**
   - `m3-graph`: `crates/xctx-graph` (agent graph, <=1 writer/repo invariant, loop & autonomy state machine, persistence).
   - `m3-channel`: `crates/xctx-channel` (contract, channel, findings, notes, redaction, scratch dir, persistence).
   - `m3-core-control`: `space::widen` in `crates/xctx-core` + M3 protocol methods & `xctx-ctl` CLI in `crates/xctx-control`.
2. **Wave 2 — UI (on top of Wave 1):**
   - `m3-ui`: `AgentGraphView`, `SharedSpacePanel`, and `LoopBar` in `crates/xctx-ui` with headless GPUI render tests.
3. **Wave 3 — Integration:**
   - `m3-app`: Wire graph, shared space, loop controls, `SpaceWiden` approval, and M3 control socket handlers into `crates/xctx`.
4. **Wave 4 — Review & dogfood hardening:**
   - Parallel reviewer swarm across `xctx-graph`/`xctx-channel`, `xctx-core`/`xctx-control`, and `xctx-ui`/`xctx`, fix findings, and dogfood a multi-agent space in `xctx`.
